# V1 technical handoff and test checklist

Current V0.9.0 packaging puts the game EXE in `Game/`, embeds the runtime in
Setup and adds desktop input plus an optional kitten-unlock save setting. See
[V1.1 setup and input bridge](INPUT-AND-SETUP-V1.1.md). The details below record
the original V1 bridge and test baseline.

V1 retains the approved installer and gameplay behavior, internal 2x rendering and the corrected 4K presentation. Its runtime optimization replaces the allocating GetRenderTargets call in PcDisplay.CanvasTransform with a reusable one-slot buffer, gated by RenderTargetCount. The buffer is used only on the graphics thread and cleared after lookup. Owned stage/canvas identity checks remain exact. This removes per-batch temporary arrays without changing game timing or rendering quality.

## Architecture

V1.0.3 names the launchers `Setup Techno Kitten Adventure.exe` and
`Techno Kitten Adventure.exe`, adds an original game icon and title-only build
badge, and migrates previous play filenames transactionally. See
[build badge and migration details](BUILD-BADGE.md).

- `src/Tka.Host`: .NET 8 WindowsDX host and opt-in regression probes.
- `src/Tka.Compatibility`: maintained PC display, native menu, storage and XNA compatibility bridges.
- `src/Tka.Installer`: package validation, transactional importing, conversion and custom setup UI.
- `src/InstallerLauncher`: native setup bootstrap and play launcher.
- `tools/Tka.AssemblyTool`: hash-verified managed IL and MonoGame adaptations.
- `tools/Tka.AssetTool`: local texture, font, shader and audio-related conversion support.

The STFS header is LIVE, title ID 584E07D2 (Indie Games), content type 2. GameInfo identifies title 58550893. There is no XEX; the original is the managed XNA Helicopter.exe. No separate DLC package has been audited. The accepted package hash is in README; the original assembly hash is `12C05F08878273BB6BF9C006D379F81C81AAF07FCF32EB3AF2DCDBB1FAB6848D`.

## Audited bridge map

These are original managed IL offsets, not native guest addresses. Patch scripts validate full source hashes and exact signatures before writing a separate assembly. Installation records a retarget report and hashes.

| Original method | Token | Original IL | Purpose |
| --- | --- | --- | --- |
| Game1 constructor | 06000001 | 0506 | Exiting ABI compatibility |
| OptionsMenu constructor | 060000F0 | 0116 | Native display rows |
| OptionsMenu.Update | 060000F1 | 0004 / 01A6 | Action translation and restoration |
| OptionsMenu.Draw | 060000F3 | 0011 | PC option values |
| Game1.Draw | 06000009 | 0000 / 0109 | Canvas begin / final presentation |
| Camera.Draw | 0600013A | 013B | Owned canvas target |
| Game1.Initialize | 06000004 | 001C | Internal stage allocation |
| Camera.Draw | 0600013A | 01A2 / 01E0 | High-resolution stage sampling |

Menu fields are resolved by managed name/type; there are no guessed CLR memory offsets. PcOptionsMenu validates original atlas identity, all five rectangles and positions, and exact menu/base types. It preserves original callbacks, Credits and Back. RuntimeAdapter separately verifies original MonoGame SHA-256 `97063554F0508C29F269892E796603C4C9041242215FFF72B0E1B87570539144`.

Popaganda uses corrected translated pixel-shader input registers matching MonoGame (position v0, color v1, UV v2). Camera transforms preserve logical 1280x720 coordinates; source origin is scaled and sprite scale compensated for the higher-resolution stage. PcDisplay fits the actual client area before mapping to the backbuffer so oversized windows do not stretch.

## Release checklist

- [ ] Build locked Release installer and verify it matches `VERSION`.
- [ ] Fresh ZIP inventory and hashes; no original assets or exposed play EXE before installation.
- [ ] Install, launch from a different working directory, play Popaganda, save, reinstall and verify backup/source preservation.
- [ ] All eight output/fullscreen combinations preserve aspect ratio.
- [ ] Internal 2x half-pixel detail, camera transforms and all five effects pass at default/saved settings; explicit 1x and invalid-value fallback pass.
- [ ] Render bridge produces identical transforms and zero measured allocations after warmup.
- [ ] Damaged package, cancellation and injected promotion failures preserve the previous installation.
- [ ] Native menu navigation, save/reload, original toggles, Credits and Back pass.
- [ ] Source archive contains only allowlisted text/source files and retained licenses.

These boxes are a reusable checklist; local release evidence is recorded separately in the developer workspace. Known limitations are listed in README. Additional hardware, controllers, long sessions and fresh dependency bootstrapping remain manual QA. Never distribute private test captures, retail assemblies or installed game assets.
